Implementation review · 7 November 2026

Historical pricing with explicit evidence and controlled provider failures

The service now has shared cooldowns, bounded batches, proxy rotation, archive RPC failover, an independent Chainlink spot fallback, and optional block-based ypriceAPI pricing.

Changes include an optional gateway deployment workflow; no production service has been deployed from this worktree. This document includes a live audit of the assets behind Yearn’s vault list, plus configuration and verification limits.

Historical sample: two closed days

One /batchHistorical request covered five underlyings on 2025-11-06 and 2026-11-06. BOLD, yCRV-f, the DOLA/sUSDe Curve LP, and the stETH Curve LP each returned matching observations on both days. The Optimism alETH/WETH Velodrome LP returned no matching observations on either day. Samples use the existing six-hour matcher; they are observations near EOD, not proof of an exact-second market price.

Priorities from this audit

  1. Trace the 78 Velodrome and 23 Aerodrome LPs through the existing pair-reserve adapter, then validate each constituent’s historical pricing and archive availability.
  2. Trace the 49 Ethereum direct misses through the appropriate Curve/share adapters; prioritize by affected vault TVL using the JSON evidence.
  3. Add independent coverage for BOLD, yYB and vbUSDS after verifying the correct feed or conversion route. The broader catalog also exposes mapping candidates such as Polygon native USDC/WETH, Arbitrum ARB and Katana AUSD.

What changed

Stored history → batched market observations → Chainlink / optional ypriceAPI → historical dependency graph → validated finalization
  • HTTP providers: shared DeFiLlama/Enso cooldowns retain the full Retry-After, including HTTP-date values. Live calls can fail promptly to another source; jobs retain the cooldown but reject waits beyond their ten-minute budget. 429/502/503/504 feedback is shared across callers.
  • Proxy routes: keep a healthy route until failure, quarantine it, and select another route even when a long provider cooldown outlasts the proxy quarantine. Body failures count as failures; caller cancellation does not mark a route broken. Public-list refreshes are bounded and coalesced.
  • Runtime support: Bun jobs use native CONNECT proxies; Workers use the optional authenticated HTTPS gateway. Gateway targets are limited to DeFiLlama and Enso, and provider credentials remain separate from gateway credentials.
  • Batching: current/historical source payloads use at most two concurrent batches. Warmup now groups its known targets by timestamp instead of calling the provider one token at a time. Malformed historical payloads remain failures, distinct from valid empty responses.
  • Independent sources: missing ENSO_API_KEY no longer disables spot pricing. Chainlink serves spot market leaves. Optional ypriceAPI is registered in historical resolution, graph repair and replay, with exact block evidence and endpoint provenance.
  • Archive RPC: ordered endpoint lists retain the original single-URL setting, use bounded per-endpoint attempts, and skip cooling endpoints before failing over. RPC Retry-After values are retained in full without sleeping through them. Historical availability still depends on the configured archives.

The existing production boundary remains: historical API reads use stored rows and bounded DeFiLlama read-through; deeper reconstruction runs in offline graph repair. Adding a source does not cause unbounded archive work during an API request.

Enable the optional pieces

Nothing needs a new database schema. See .env.example. Existing deployments continue with direct provider access until configured.

Bun jobs and public proxy candidates

PRICE_PROXY_PUBLIC_LIST=true bun run repair:historical --limit 10
# Optional operator-managed pool/list instead:
PRICE_PROXY_URLS=http://proxy-a.example:8080,https://proxy-b.example:8443
PRICE_PROXY_LIST_URLS=https://your-proxy-list.example/proxies.txt

The first command retains the repair script’s default dry-run mode. Public candidates come from Proxifly’s published list, refreshed at most every 15 minutes, with up to four list URLs and 512 candidates. Downloaded entries must be public IPv4 endpoints. Candidate reachability is learned from real provider requests; the list is not a guarantee of reliable proxies. TLS verification stays enabled.

Cloudflare Worker

# Run the gateway under Bun behind your HTTPS reverse proxy:
PRICE_GATEWAY_TOKEN=<secret> PRICE_PROXY_PUBLIC_LIST=true   bun run scripts/provider-gateway.ts

# Configure these on the Worker:
PRICE_GATEWAY_URL=https://your-gateway.example/
PRICE_GATEWAY_TOKEN=<the same secret>

The gateway listens on port 8788 by default (override PRICE_GATEWAY_PORT). It has an eight-second upstream timeout, 32-request concurrency cap and 8 MiB response cap. HTTP(S) proxy settings alone do not work in Workers; the code reports that configuration error. The optional CI deployment uses a separate Cloudflare Worker and a single Bun container. It requires Workers Paid and Containers access. Configure yearn-price/prd_gateway in Doppler, then set repository variables DOPPLER_GATEWAY_IDENTITY_ID and PRICE_GATEWAY_DEPLOY_ENABLED=true. CI builds before loading credentials, syncs only gateway settings, deploys, and waits for authenticated container health before the pricing Worker deploy. PR checks build the Worker and Linux image without secrets. See the deployment runbook for the exact setup. Secrets and activation are still required; the job is disabled by default. Proxy health and cooldown state reset on container replacement.

Historical ypriceAPI and archive backups

YPRICEAPI_SIGNER=<issued signer>
YPRICEAPI_SIGNATURE=<issued signature>
YPRICEAPI_URL=https://ypriceapi-beta.yearn.finance
RPC_URL_1=https://primary-archive.example
RPC_URLS_1=["https://backup-archive.example","https://another-archive.example"]

Use the same RPC_URLS_<chainId> pattern on each supported chain. Enabling ypriceAPI requires both credentials and an RPC to resolve timestamps to blocks. The source preserves the block timestamp, caches successful block prices, and never stores provider failures as zero prices. Signed ypriceAPI requests use direct TLS with their own shared cooldown; proxy/gateway routing is limited to DeFiLlama and Enso.

Proxy rotation does not remove account-wide provider quotas, restore missing history, or make an unsupported token priceable. The full Retry-After still applies before retrying through another route.

Gateway deployment follows Cloudflare’s container model and the existing Yearn Cloudflare/Doppler workflow conventions.

Verification and remaining limits

  • TypeScript compilation passes for the pricing and gateway Workers. Both Wrangler dry-run bundles and the Linux gateway image build completed; Sentry dependencies emit Node-compatibility warnings that still need deployment/runtime review.
  • Added regression cases for optional source wiring, block evidence, malformed payloads, proxy rotation and timeout/body failures. Test and lint suites were not run, as required for Astra. A local container readiness check confirmed the health route, authentication response, and non-root runtime.
  • Live read-only evidence: seven current-price batches covering 346 unique underlyings; one historical batch covering five tokens on two dates. No production rows were written.
  • The public proxy list URL returned HTTP 200. No external proxy was used to forward secrets; no gateway or authenticated ypriceAPI deployment was exercised.
  • No local .env or .dev.vars was present. Deployed RPC configuration, Enso coverage, on-chain adapter success, and production database completeness remain unverified.

“Any day on any chain without issues” is not a guarantee any provider can supply. The implementation improves independence and failure handling while preserving an explicit unresolved state when there is no supported historical observation.
