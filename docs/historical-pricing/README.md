# Unresolved historical prices

For the design and examples, see [how historical graph backfill and coverage tracking work](architecture.md).

The database is authoritative for stored prices and recorded unresolved targets.
The JSON files here are local diagnostic snapshots, excluded from Git. They are
not a second maintained source of truth; reconcile them against the database
when preparing a run. GitHub issues track follow-up work rather than duplicate
the database inventory.

`unpriced-assets.json` is a local asset/day snapshot. Assets are keyed by
chain ID and contract address. Observations distinguish roots from dependencies,
retain run IDs, and record the latest unresolved reason or candidate status.
Candidate does not mean stored.

Merge completed graph results from new historical queries:

```bash
bun run inventory:historical --graph path/to/run.jsonl.graph.json \
  --inventory docs/historical-pricing/unpriced-assets.json --run unique-run-id
```

Merge runs chronologically. Repeating a run is idempotent. A run ID cannot be
reused for different evidence. Raw artifacts stay outside Git; run digests
identify the supporting evidence. Retryable errors and graph cutoffs remain
distinct from confirmed missing observations.

## Expected gaps after backfill

Use the completed local backfill as the expected production result. Successful
local results are treated as filled; confirm equivalence after production runs.
The main planning list is `post-backfill-projection.json`, with the readable
[post-backfill snapshot](coverage-snapshot.md). It traces only unresolved original
requests to the assets needing their own pricing work. Dependent pools, resolved
requests and unused graph branches are excluded. Every listed date remains
unresolved by that backfill.

```bash
bun run scripts/report-post-backfill.ts \
  --run path/to/completed-backfill.jsonl \
  --graph path/to/completed-backfill.jsonl.replay.jsonl.graph.json \
  --inventory docs/historical-pricing/unpriced-assets.json \
  --coverage path/to/coverage.json \
  --out docs/historical-pricing/post-backfill-projection
```

The broader inventory and source-availability analysis below are research inputs,
not predictions of backfill success. Finding a price in that research alone does
not remove a date from the projection of a completed backfill.

## Historical availability research

Choose the cutoff from the current UTC date whenever you run the analysis; do
not reuse the date of an earlier report. The script accepts only completed UTC
days, so use yesterday as `--end`, not today's still-open day. This example
calculates that cutoff automatically:

```bash
COVERAGE_END="$(date -u -d yesterday +%F)"
bun run coverage:historical \
  --inventory docs/historical-pricing/unpriced-assets.json \
  --graph path/to/run.jsonl.graph.json \
  --out backfill-runs/coverage --start 2015-07-30 --end "$COVERAGE_END"
```

This reads stored history through the closed-day cutoff and daily market history
using batched `/prices/first` bounds and multi-coin `/chart` requests: at most
500 total points and 365 days per request (five identifiers means 100 days),
and a 12-hour matching window. Requests share pacing and Retry-After cooldowns.
Successful responses are cached for restart; failed windows remain retryable.

The report distinguishes stored EOD coverage, any-time stored rows, and direct
or eligible-alias provider coverage. Requested missing dates are classified as
leading, trailing, interior, now-covered or no-observed-coverage. An asset may
have several gap types. Failed source windows mark an investigation incomplete.

The daily market scan is not an exhaustive lifetime adapter replay. Adapter
results establish coverage only on their requested dates. No observations does
not establish that an asset never had economic value. First price is not
deployment date; deployment remains unverified until code evidence is attached.
No interpolation, peg assumptions, spot substitutions or new adapters are used.

Related work: https://github.com/yearn/yearn-prices/issues/43 and
https://github.com/yearn/yearn-prices/issues/26.

## Investigation list versus dependency impact

`unpriced-assets.investigation.json` is the broad investigation inventory generated by the merge command; use `post-backfill-projection.json` for the remaining work after a particular backfill. It excludes dates where a discovered, error-free route is blocked only on missing child prices. The full `unpriced-assets.json` retains those observations as dependency impact records with `pricingNeed: dependency` and `blockedBy` links. Missing routes, invalid state, retryable failures, cycles and budget cutoffs remain actionable. An asset with mixed failures stays in the list for dates requiring its own investigation. The coverage command uses this same per-date filter; token suffixes do not determine inclusion.
