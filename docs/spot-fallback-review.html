Price service · Phase 1 · Local implementation review

More spot prices from the existing resolver

When Enso has no usable quote, DeFiLlama can now supply a current USD price before on-chain derivation. The same fallback is available for underlying tokens, allowing a new constituent price to unlock a vault or pool.

Enso (10) → DeFiLlama current (15) → On-chain derivation (20)

Behavior to review

AreaImplementation
Source precedenceSuccessful Enso quotes remain preferred. DeFiLlama can replace a previously derived quote; the benchmark reports source changes and disagreements.
BatchingConcurrent lookups coalesce, duplicate token lookups share results, and provider batches have bounded concurrency.
Provider failuresMalformed envelopes, rate limits and transport failures remain errors. A failed batch is not retried token by token.
Rate limitsA shared cooldown within the Worker isolate honors the full Retry-After. This is not a cross-isolate quota coordinator.
ObservationsPreserve provider timestamps. Match the existing current-price policy: at most six hours old and five minutes ahead.
Historical storageSpot quotes are not persisted as historical closes. Historical sources and backfill behavior are unchanged.

Coverage comparison

Benchmark instructions describe how to compare Enso + derivation against Enso + DeFiLlama + derivation. Both graphs share market observations; each target gets an independent derivation budget.

  • JSON and optional HTML reports show priced, missing and error outcomes.
  • Direct and derived recoveries are distinguishable, as are recovery from absence and recovery from provider failure.
  • Source changes and price disagreements remain visible even when both graphs return prices.

Validation and limits

TypeScript checking passes. Focused tests were added but remain unrun, along with lint, under the repository's Astra instruction. Independent code review checked batching, cancellation, source wiring and benchmark cache behavior.

No live coverage gain has been measured in this change. The benchmark uses live provider/RPC access even with a saved target file. Its cached comparison timings are not production latency measurements.
